Object Deformability Score Calculation

This page presents the complete experimental and computational methodology used to determine the Object Deformability Score (QO) for the 21 objects included in the GRAB benchmark. The procedure combines controlled object compression, 3D reconstruction, point-cloud preprocessing, geometric registration, and Density-Aware Chamfer Distance (DCD) to quantify object deformation.

The following sections explain each processing stage, from acquiring the original 3D object geometry to calculating the final deformability score. Experimental figures, reconstruction demonstrations, and point-cloud alignment visualizations are provided to illustrate the complete workflow.

Methodology Overview

The calculation of object deformability follows six main processing stages. Each stage prepares the object geometry for accurate comparison between its undeformed and compressed states.

1. Object Deformability as a Graspability Attribute

In the GRAB benchmark, the Object Deformability Score (QO) characterizes the deformation behaviour of objects as a pre-grasp graspability attribute. The dataset comprises 21 distinct objects across seven inorganic contaminant categories, with three representative items per category. All objects weigh less than 100 g and fit within a bounding volume of 20 × 10 × 10 cm³, ensuring compatibility with the grippers' operational constraints. Unlike conventional datasets dominated by rigid objects, GRAB includes objects with diverse geometric and deformation characteristics. Since object weight and dimensions were constrained, deformability was selected as the primary object-related property influencing graspability, quantified through QO prior to grasp execution.

To quantify this property, each object is examined in two physical states: before compression and during compression. The geometric differences between these states are measured using DCD, allowing objects with different deformation characteristics to be compared through a consistent measurement procedure.

2. Experimental Setup for Deformation Measurement

A customized experimental platform was developed to acquire 3D representations of objects before and during controlled compression. This enables object deformation to be measured through changes in the reconstructed geometry rather than relying solely on visual inspection. The setup consists of a UR10 robotic manipulator equipped with an OnRobot RG2 parallel gripper and customized compression pads. An Intel RealSense D415 RGB-D camera, integrated with RecFusion 3D reconstruction software, is used to capture the object's geometry. A controlled compression force of 40 N is applied independently along the x and y axes. Evaluating both directions helps account for objects that deform differently depending on the direction of the applied force.

2.1. Controlled Compression Procedure

For each object, the measurement procedure begins by obtaining its geometry in the undeformed state. The robotic gripper then applies the specified compression force while the object is scanned in its compressed configuration.

The procedure is performed independently along both compression directions, producing two deformation measurements for each object. The same processing workflow is then applied to each pair of reconstructed point clouds.

2.2. 3D Reconstruction and Point-Cloud Acquisition

The next stage involves reconstructing the three-dimensional geometry of the object in its undeformed and compressed states. RecFusion is used to generate these 3D representations from RGB-D measurements captured using the RealSense camera.

During reconstruction, depth measurements are projected into 3D space using camera intrinsic parameters. Successive measurements are registered and integrated through Truncated Signed Distance Function (TSDF) fusion to produce a dense representation of the object's geometry.

Step 1 — Reconstruct the Object Geometry

First, the object is scanned in its undeformed state using RecFusion. A second reconstruction is obtained while the compression force is applied. These reconstructions capture the geometric changes caused by compression.

Step 2 — Export the Reconstructed Meshes

The reconstructed 3D geometries are exported as mesh files for further processing. Separate mesh representations are retained for the undeformed and compressed states.

Step 3 — Prepare Binary Point-Cloud Data

The exported ASCII-formatted geometry data are converted into binary format for subsequent point-cloud processing. This conversion prepares the data for filtering, alignment, and geometric comparison.

The repository includes the Python script binary_ascii.py for ASCII-to-binary conversion.

2.3. Point-Cloud Preprocessing and Alignment

Although RecFusion provides detailed 3D reconstructions, the exported data may contain points belonging to the experimental platform, gripper, background, or other surrounding components. These unwanted points must be removed before comparing the object's geometry.

Step 1 — Point-Cloud Filtering

Spatial cropping and colour-based thresholding are performed using RecFusion and MeshLab to isolate the target object. This reduces the influence of background geometry and unrelated points on the deformation measurement.

The repository also includes color_filter.py, a Python script associated with colour-based filtering.

Following preprocessing, the undeformed and compressed point clouds must be brought into a common coordinate frame. Without proper alignment, differences in object position or orientation could be incorrectly interpreted as deformation.

To address this, a two-stage point-cloud registration procedure is employed.

Step 2 — Coarse Alignment Using MeshLab

The principal axes of the two point clouds are aligned using MeshLab to establish an initial geometric correspondence. This step reduces major differences in object orientation and positioning.

Coarse alignment provides a suitable initialization for the subsequent fine-registration procedure.

Step 3 — Fine Alignment Using ICP

Following coarse alignment, the Iterative Closest Point (ICP) algorithm is applied to refine the registration between the two point clouds.

ICP iteratively establishes point correspondences and estimates the transformation that reduces residual geometric distances between the two representations. This minimizes positional differences while preserving the geometric changes caused by object deformation.

The repository includes icp_alignment.py for point-cloud registration.

After preprocessing and registration, the two aligned point clouds represent the same object in its undeformed and compressed configurations. They can now be compared using a geometric distance metric to quantify deformation.

2.4. Density-Aware Chamfer Distance (DCD) Calculation

The final geometric comparison is performed using Density-Aware Chamfer Distance (DCD), which measures the discrepancy between two aligned 3D point clouds.

Let \(S_1\) represent the point cloud obtained before compression and \(S_2\) represent the corresponding point cloud acquired during compression. DCD compares these representations by considering the distances between corresponding nearest-neighbour points, together with local point-density information.

Unlike conventional Chamfer Distance, DCD incorporates density-aware normalization to account for differences in point sampling. This is particularly relevant when comparing reconstructed point clouds that may have nonuniform point distributions.

\[ \begin{aligned} d_{\mathrm{DCD}}(S_1,S_2) = \frac{1}{2}\Bigg( &\frac{1}{|S_1|} \sum_{x\in S_1} \left( 1-\frac{1}{\hat{n}_y} e^{-\alpha\|x-\hat{y}\|_2} \right) \\[10pt] +\;&\frac{1}{|S_2|} \sum_{y\in S_2} \left( 1-\frac{1}{\hat{n}_x} e^{-\alpha\|y-\hat{x}\|_2} \right) \Bigg) \end{aligned} \]
(6)

Understanding the DCD Equation

The equation evaluates geometric differences in both directions: from the undeformed point cloud to the compressed point cloud, and from the compressed point cloud back to the undeformed point cloud. The two contributions are averaged to obtain a symmetric distance measure.

Explanation of Mathematical Terms

\(S_1\): Point cloud representing the object before compression.

\(S_2\): Point cloud representing the object during compression.

\(\hat{y}\) and \(\hat{x}\): Nearest-neighbour points in the opposite point cloud.

\(\|x-\hat{y}\|_2\): Euclidean distance between a point and its nearest neighbour.

\(\hat{n}_y\) and \(\hat{n}_x\): Local point-density normalization factors.

\(\alpha\): Parameter controlling the sensitivity of the exponential distance term to geometric deviations.

How DCD Quantifies Object Deformation

For each point in the undeformed point cloud, the nearest corresponding point is identified in the compressed point cloud. The geometric distance between these points contributes to the DCD calculation. The same comparison is then performed in the reverse direction.

The exponential distance term converts geometric discrepancies into bounded contributions, while the density-aware factors account for differences in point distribution. Small geometric discrepancies generally produce lower DCD values, whereas larger discrepancies produce higher values.

Accordingly, objects that undergo greater geometric changes under the applied force tend to exhibit higher DCD values. Objects that retain their original geometry tend to produce lower values.

3. Calculating the Final Object Deformability Score

Since an object's deformation response may depend on the direction of compression, the DCD measurement is performed independently for the x-axis and y-axis compression experiments.

Each direction produces a DCD value by comparing the corresponding undeformed and compressed point clouds after preprocessing and alignment. These two directional measurements are then averaged to determine a single Object Deformability Score (QO) for each object.

\[ Q_O = \frac{ d_{\mathrm{DCD}}^{(x)} + d_{\mathrm{DCD}}^{(y)} }{2} \]

Here, \(d_{\mathrm{DCD}}^{(x)}\) and \(d_{\mathrm{DCD}}^{(y)}\) represent the DCD values obtained from compression along the x and y directions, respectively. Their arithmetic mean provides the final object-level deformability score.

Interpreting the Final Score

Higher QO values: Indicate greater geometric deformation under the applied compression force.

Lower QO values: Indicate smaller geometric changes, corresponding to relatively rigid objects.

This procedure is repeated for each of the 21 objects, resulting in one final deformability score per object. The scores can then be compared across individual objects and contaminant categories to characterize their relative deformation behaviour under consistent experimental conditions.

4. Object Deformability Score Results

The complete methodology was applied to 21 objects from seven inorganic contaminant categories. For each object, the reconstructed geometries were processed, aligned, and compared using DCD to obtain the final deformability score.

The resulting scores reveal differences in the deformation characteristics of the investigated objects. Mesh bags and plastic bags exhibit the highest average deformability scores, whereas tin cans exhibit the lowest average score among the seven categories.

Category-Wise Deformability Comparison

These results demonstrate that the DCD-based methodology captures differences in object deformation across the dataset. The calculated QO values serve as the object-related pre-grasp attribute within the GRAB benchmark, supporting subsequent analysis of the relationship between object deformability and robotic grasping performance.

Relevant scripts include binary_ascii.py for ASCII-to-binary conversion, color_filter.py for colour-based point-cloud filtering, and icp_alignment.py for point-cloud registration. The repository also contains the Density-Aware Chamfer Distance implementation.
